# 002 Typed SDK for the app (`packages/sdk`)

- **Owner:** Spare
- **Status:** done
- **Reviewer:** Lead

## Why
The Expo app (Android, iOS, web) talks to the API only through this package. It must be typed, offline-tolerant and realtime-aware, and it must run in React Native and the browser (no Node-only APIs: no `fs`, no `node:crypto`, no Buffer).

## Scope
Create `packages/sdk` (`@farmgo/sdk`, ESM TypeScript source like the other packages, `exports: { ".": "./src/index.ts" }`), depending only on `@farmgo/contracts` and `zod`.

1. **HTTP client** `createApi({ baseUrl, getToken, getOrgId?, onUnauthorized?, fetchImpl?, language? })`.
   - Sends `Authorization: Bearer`, `X-Org-Id` when set, `Accept-Language`.
   - Namespaced methods for every endpoint in the OpenAPI docs (`api.orders.list(q)`, `api.orders.get(id)`, `api.orders.pay(id, body)`, `api.supply.create(body)`, ...), argument types from `@farmgo/contracts` inputs. Response types: use the `*Dto` schemas from contracts when they exist (Backend ticket B01 is adding them); until then a hand-written interface per response in `src/types.ts` matching the real JSON. Keep the method list complete: generate a checklist from `/docs/openapi.json` and tick every path.
   - Throws `ApiError { status, code, message, requestId, details }` parsed from the API's error body; network failures become `ApiError { code: 'NETWORK' }`.
   - Every write gets an `Idempotency-Key` (random UUID from `crypto.randomUUID` or a small fallback) unless the caller passes one.
2. **Offline outbox** `createOutbox({ storage, api })`: queue a write while offline with its idempotency key, persist it (pluggable storage interface: get/set/remove, the app provides MMKV or AsyncStorage), replay in order when back online, stop on 4xx and surface the failure, retry 5xx/network with backoff. Expose `pending()` and a subscribe callback for UI badges.
3. **Realtime** `createRealtime({ url, getToken })` for `wss://.../ws?token=`: `subscribe(channel, handler)` returns unsubscribe; tracks `lastSeq` per channel and resubscribes with it after reconnect; exponential backoff with jitter; app-level ping every 20 s; emits `resync` for a channel when the server sends `type: 'resync'`; `status` observable (`connecting`, `open`, `closed`). Protocol is in `packages/contracts/src/realtime.ts`.
4. **Uploads** `uploadFile(api, { bucket, uri | blob, contentType, size })`: presign, PUT to the returned URL with the returned headers, return the object key.
5. **Money and dates helpers:** `formatKes(cents, { lang })` (KES 1,520 style, no decimals when whole), `parseKesInput(text) -> cents`, and ISO helpers. Pure functions, unit tested.

## Tests
- Unit tests (vitest) with a mocked fetch for errors, idempotency, outbox replay order and failure handling, realtime reconnect with `lastSeq` (mock WebSocket).
- One integration test file that boots the real API with `buildApp` from `apps/api` against the test database (reuse `apps/api/test/helpers.ts` patterns) and runs a buyer sign-in, `me`, `supply.list`, `orders.create` through the SDK.

## Acceptance
Every path in the OpenAPI document has an SDK method; lint, typecheck and tests green; README section in `packages/sdk/README.md` with a 20-line usage example. Message the Lead when done.

## Notes (Spare, 2026-09-26)
- Package at `packages/sdk` (`@farmgo/sdk`), ESM TypeScript source. Runtime deps: `@farmgo/contracts` and `zod` only. No Node APIs in `src` (its tsconfig uses lib DOM and no `@types/node`).
- All 114 operations in the dev API's OpenAPI document have a method. Checklist: `packages/sdk/ENDPOINTS.md`, generated by a script that fails when a path has no method. `POST /v1/orders/:id/confirm-receipt` is in the API source but not in the running dev API yet; the SDK has `orders.confirmReceipt` for it. Better Auth paths are wrapped under `api.auth` (email sign-up and sign-in, phone OTP, session, sign-out) because the integration test and simple flows need them. Provider webhooks are under `api.webhooks` for QA tooling only.
- Response types are hand-written in `src/types.ts` (B01 DTOs have not landed). Request types come from contracts through `Input<typeof Schema>`, which turns Zod coerce fields (`unknown` on the input side) into `Date | string` and numbers.
- Tests: 38 unit tests (mocked fetch and WebSocket) plus one integration file that boots `buildApp` on a random port and drives sign-up, sign-in, me, buyer and farmer onboarding, phone OTP, supply.list, orders.create with an idempotency replay, error mapping, and a real WebSocket order event. 45 tests, lint and typecheck green.
- `packages/sdk/turbo.json` makes the SDK `test` task depend on `@farmgo/api#test`: both use `farmgo_test`, and the API's global setup truncates it, so running them side by side would be flaky.
- Found while testing: the realtime gateway attaches its `message` listener only after the auto-join queries and `hello`, so a `subscribe` sent right at socket open is silently dropped. The SDK subscribes after `hello`. A backend fix (attach the listener first, or buffer) would protect other clients.
- CI (`.github/workflows/ci.yml`) runs contracts, core and api tests only; the SDK tests are not in CI yet.
- Root `pnpm lint` currently fails on `apps/app/tsconfig.json` formatting (Lead-owned file, not touched here). `biome check packages/sdk` is clean.
